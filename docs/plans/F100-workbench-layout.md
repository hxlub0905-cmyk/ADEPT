# F100：畫布橫躺在上面，工作台在下面（2026-09-08）

2026-09-08 的外部 UI/UX 評審（F99）對版面配置的結論，使用者定調「版面按照你的
建議改」。這一份寫的是**為什麼要動結構、動成什麼樣、代價是什麼、怎麼驗收**。

## 1. 三個結構性的毛病

現在（U5 之後）的版面是三欄：左邊卡片庫、中間一欄上畫布下設定區、右邊一欄
預覽影像。

```
現在（Tune）
┌─庫─┬──畫布（窄、矮）──┬──預覽影像（大）──┐
│    ├──────────────────┤                  │
│    │ 設定區 │ 儀表板  │  Verdict         │
└────┴──────────────────┴──────────────────┘
```

三個毛病都不是調數字調得掉的：

* **pipeline 是橫著流的，畫布卻是一格窄的直立空間。** 六張卡橫排要 1,900 px
  寬，中欄只有 580 px，所以永遠得縮到 50%——而 50% 在 `_LOD_TERSE`（0.55）之下，
  卡片只剩標題。這是「卡片讀不到字」的根本原因，不是 LOD 門檻的問題。
* **畫布和設定區搶同一欄的高度。** 選一張卡設定區攤開，畫布剩 280 px（1366×768
  上 230 px，GLV 卡本人在畫面外）。兩個都是使用者要看的東西，卻綁在同一根
  splitter 上互相擠。
* **右欄的預覽影像有硬的最小寬度，而且 Build 模式也不讓。** 載入 recipe 選到
  GLV 卡之後 `minimumSizeHint` 變成 1,334 寬、視窗實際 1,495——比 1366 那台
  機器的螢幕還寬。U1 的 `fit_screen` 守的是開窗那一刻，沒有守住載入之後。
  而 Build 模式只把中欄的設定區收掉，預覽仍然吃一半螢幕，畫布還是螢幕上第三大
  的東西（U5 自己的說明就這樣寫）。

## 2. 新版面

```
┌─庫─┬──────────── 畫布（全寬、橫流）────────────┐
│    │  [Load]→[ROI]→[ROI]→[ROI]→[GLV]→[Report]  │
│    ├───────────────┬──────────────┬─────────────┤
│    │ 設定區        │ 儀表板       │ 預覽影像    │
│    ├───────────────┴──────────────┴─────────────┤
│    │ Verdict  more than one box is off · score 10.42 · Path: …
└────┴────────────────────────────────────────────┘
```

* **畫布吃滿卡片庫右邊的整個寬度**，高度由一根橫向 splitter 決定。1366 寬時
  六張卡在 70% 縮放排得下一排。
* **工作台三格並排**：設定區｜儀表板｜預覽影像。設定區、儀表板、影像在同一條
  水平線上——這正是 U8「儀表挨著參數」的決定，而且影像不再跟畫布搶高度。
* **Verdict 是一條常駐的結論列**，橫跨在工作台下面、Problems 列上面。它不在
  splitter 裡，所以 Build 模式收掉工作台之後它還在。P1-2（預覽停在選到的卡時
  說一句為什麼）的那句話也住在這裡。
* **Build 模式**＝工作台收到 0、畫布 fit。這才是「看全貌」。
* **Tune 模式**＝工作台開著（**開窗就開著**，因為影像住在裡面），畫布保底
  `CANVAS_MIN_PX`（200 px，768 高的螢幕上約 35%）、預設 40%。
* **卡片庫維持左邊的窄軌。** 從 Build 切到 Tune 時把卡片區收成只剩 rail
  （58 px），工作台拿到那 200 px；rail 上點一下就回來。開窗時**不**收——
  空白狀態下卡片清單是使用者第一眼要看的東西。

這個形狀就是 n8n 節點詳情面板換個方向：n8n 是「輸入｜參數｜輸出」三格，這裡是
「參數｜量出來的數字｜影像」三格。

## 3. 兩條不走的路

* **n8n 那種全螢幕畫布加右側滑出面板。** 那在 n8n 成立是因為資料預覽就在面板
  裡。這裡使用者一邊拖滑桿一邊看影像，面板滑出來蓋住影像，迴圈就斷了。
* **只調數字不改結構**（Tune 改成畫布 3 設定 2、預覽最小寬度降到 300）。可以讓
  1366 裝得下，但畫布還是窄的直立格，卡片還是要縮。止痛不是治病。

## 4. 做法

* 版面模式的邏輯搬進**新模組 `ui/workbench.py`**（`WorkbenchLayout`），
  `studio.py` 只留建 widget 與轉呼叫——`CLAUDE.md` §4 那條「新的面板一律開新
  模組」，而 `test_size_ceilings.py` 的 7,444 不往上。
* 名字**盡量不改**，讓既有測試改最少：`canvas_column` 仍是「畫布在上」的直向
  splitter（`widget(0)` 仍是畫布，`canvas.py::_build_header` 靠著它）；
  `params_row` 仍是 `stack` ＋ `gauge_pane` 那根橫向 splitter，只是多了第三格
  `preview_pane`，別名 `workbench`。`root_splitter` 從三欄變兩欄：
  `[library, main_column]`。
* `params_open` 的意思從「設定區攤開」變成「**工作台攤開**」。Tune 模式開窗就
  是 True；`set_params_open(False)` 仍然把工作台收到 0（那是使用者手動收的）。
  選到卡片會把收起來的工作台再打開（`_sync_params_pane`），**取消選取不再自動
  收起來**——影像住在裡面，收掉它等於把影像藏起來。
* QSettings：`ui/columns` 從三個值變兩個（舊值長度對不上會自動退回預設）；
  Tune 的畫布/工作台比例換**新的一格** `ui/canvas_split_tune_f100`——舊那一格
  存的是「畫布 2 / 設定 3」，套到新版面上畫布會低於保底。工作台三格的寬度存在
  `ui/workbench_columns`。
* 分數直方圖早就住在 Results 視窗，這一輪不動。

## 5. 要重寫的測試

`test_ui_layout_modes.py`（U5/U8 的座標測試）、`test_ui_f8_ui_polish.py` 的
兩條版面測試、`test_ui_results.py::test_main_window_keeps_only_the_editing_surface`
與 `test_preview_gets_the_widest_column`、`test_ui_studio_m5.py` 的三欄斷言。
每一條改的都是**斷言的形狀**，不是它問的問題：畫布還是只有一份、切模式不重建、
儀表還是挨著參數、影像還是有自己的一格。

新的一條（F99 P2-7 的雛形）：在 1366×768 開視窗、載 recipe、選 GLV 卡之後，
視窗的 `minimumSizeHint().width()` ≤ 1366、畫布高度 ≥ 主欄的 35%。那是這一輪
的驗收，也是 F99 P0-3 的關門。

## 6. 代價，講在前面

* 使用者調過的 Tune 比例會重設一次（換了 QSettings 鍵）。
* 卡片庫在 Tune 模式下會被收成 rail——一次，而且只在從 Build 切過來的時候。
* 兩個模式的 splitter 記憶方向沒變（都是直向），但預設值變了。
