# F88：把四張寫死的圖換成一個 graph builder

> 狀態：**計畫書，還沒動程式碼。**
> 起點：使用者 2026-09-07 —— 「希望他最終能像 JMP 內的 Graph builder 一樣
> 或可以畫出很漂亮的圖表」、「我還是傾向做 graph builder like 的模式」。

---

## 0. 一句話

**一張圖不再是「從四種裡挑一種」，而是「把哪一欄放到哪一個角色上」** ——
X、Y、顏色、大小、分組，再挑一種記號（點／線／柱／盒／方格）。

---

## 1. 為什麼這件事比它看起來小

因為**現在那四張圖已經是這個文法了**，只是被寫死成四個組合：

| 現在那張 | X | Y | 顏色 | 記號 |
|---|---|---|---|---|
| Box plot | 區域 | 統計量 | 區域 | 盒 |
| Histogram | 統計量 | 次數 | 區域 | 柱 |
| Position profile | 位置 x | 統計量 | 區域 | 點＋線 |
| Heat map | 位置 x | 位置 y | **統計量** | 方格 |

⚠ **熱圖跟散佈圖只差在「顏色綁的是區域還是統計量」。** 這一列是整份計畫書的
根據：使用者想要的那些圖（XY 散佈、排序長條、一列一條線）不是三個新功能，
是同一個引擎的三種角色配置。

反過來說，這也是**風險**：四張圖各自有寫死的細節（盒鬚圖的類別軸、熱圖的
格子鋪法、profile 的趨勢線），一般化的時候那些細節不能掉。**分刀的順序就是
為了讓它們一次掉一個、而且掉了看得出來**（§7）。

---

## 2. 資料模型：一張長表

現在 `chart_series` 產的是「四張圖各自需要的形狀」
（`groups[{name, colour, values, cx, cy, rects}]`），也就是**資料的形狀跟著
圖走**。文法要的相反：**一份資料，很多種看法**。

```
region   box   x     y     glv_mean  glv_median  glv_std  …
epi      0     70    90    112.0     111.8       2.1
epi      1     160   90    112.9     112.7       2.0
mg       0     600   90    128.3     128.1       3.4
```

一列一格框，**每一個量出來的統計量各一欄**。

⚠ **這一步就算之後不做 graph builder 也值得**：長表可以直接寫成 CSV，
而「每一格框一列」是使用者遲早會要的東西（現在的 `defects.csv` 是一顆
defect 一列，看不到格）。所以第一刀單獨出貨就有價值。

新模組：`core/export/chart_frame.py`
* `build_frame(notes, colours) -> Frame`（`Frame = {columns, rows}`，純資料）
* `Frame.column(name)`、`Frame.numeric_columns()`、`Frame.to_csv()`

`chart_series` 暫時留著（四張舊圖還在用），第四刀才拆。

## 3. 圖的規格：一份 spec 進 recipe

```json
{"mark": "point", "x": "x", "y": "glv_mean",
 "color": "region", "size": "", "group": "region"}
```

住在 `core/pipeline/chart_spec.py`，跟 `chart_style` 同一個形狀與同一條界線：

* **驗的是形狀**（角色名合不合法、mark 在不在那張表上、欄名是不是字串），
  **不驗欄位存不存在** —— 那要資料才知道，而 recipe 存的時候沒有資料。
  欄位不存在是**跑的時候**一條說得出話的警告（同 `Which number to plot`
  打錯時畫布上那條黃字）。
* ⚠ **它不 import `export`。** mark 是一組**封閉的字彙**
  （`point` / `line` / `bar` / `box` / `cell`），由這一支驗；
  「那個字要怎麼畫」是 `export` 的事。跟 `chart_style` 不認識圖的名字是
  同一條規矩，而那條規矩已經付過一次帳（見 F87 的 `resolve_style`）。
* round-trip 是 identity（鐵則 9）。

## 4. 畫的那一側：mark × scale

新模組 `core/export/chart_draw.py`：

```
draw(frame, spec, style, width, height) -> svg 字串
```

裡面只有兩件事一般化：

**scale** —— 一欄 → 畫布座標。三種：
* `linear`（數值）
* `band`（類別：區域、或任何非數值欄）
* `position`（位置欄；`cell` mark 用它做格子鋪法，見 F87 的 `heat_lattice`）

**mark** —— 一列（或一群）→ 一段 SVG。五種，各自宣告**它要哪幾個角色**：

| mark | 必要角色 | 選用 | 現在誰在做 |
|---|---|---|---|
| `point` | x, y | color, size | `_svg_profile` 的圓圈 |
| `line` | x, y | color | `_svg_profile` 的折線／趨勢線 |
| `bar` | x, y | color | `_svg_histogram` |
| `box` | x（類別）, y | color | `boxplot.build_boxplot_svg` |
| `cell` | x, y, **color** | — | `_svg_map` |

⚠ **`box` 與 `bar` 會做聚合**（盒鬚圖把一群值收成五個數、直方圖收成次數），
其餘三種是一列一個記號。那個差別要寫在 mark 的宣告裡，不要藏在畫圖的程式碼
中間 —— 不然「為什麼這張圖的點變少了」沒有地方回答。

**`chart_style` 一格都不動**：字級、線寬、填色、鎖定範圍照舊，它們本來就是
「長什麼樣」而不是「畫什麼」。`GLOBAL_APPLIES` 那張「哪一格對哪張圖有意思」
的表改成**對 mark** 而不是對圖名。

## 5. UI：插槽 ＋ 預設

**不做拖曳。** d4t 已經有「插槽」那套語言（`ui/wiring_slot.py`：一個符號、
現在接的是什麼、一顆「換」），而拖曳要另外教一次。

```
Mark   [● 點] [— 線] [▮ 柱] [⊟ 盒] [▦ 方格]      ← 一排膠囊（F68 的文法）
X      [ box centre X        ▾ ]
Y      [ glv_mean            ▾ ]
Colour [ region              ▾ ]
Size   [ (none)              ▾ ]
```

⚠ **打開時一定是一個預設，不是一片空白。** Graph builder 最容易讓不寫 code
的人卡住的就是「面前一張白紙」，而那直接違反推廣鐵則。現有四張變成四個預設
（`Box plot` / `Histogram` / `Position profile` / `Heat map`），使用者從其中
一個開始改。JMP 自己也是這樣。

新模組 `ui/graph_builder.py`；`ui/uniformity_window.py` 變成它的容器。

## 6. 不准打破的（這一輪最重要的一段）

1. **畫面上的圖跟寫出去的逐位元組相同** —— `core/export` 產 SVG，UI 用
   `QSvgRenderer` 畫同一個字串。graph builder 不准為了「即時」另外畫一份。
2. **`freeze_golden.py --check` 三份逐項相同** —— 這一輪不動任何演算法，
   數字一個都不該變。
3. **四張預設畫出來要跟今天一樣** —— 而且要**逐位元組**比對得出來。
   這是第四刀唯一的驗收標準（見 §7）。
4. **一格設定只能有一個家**（F87 第十一刀踩過）。
5. **一格答了也沒用的設定，比沒有那一格更糟** —— mark 不用的角色要收起來
   （`cell` 沒有「大小」、`bar` 沒有「大小」），走 F87 那套
   `*_APPLIES` 的既有機制。

## 9. 四個問題，使用者 2026-09-07 已經答完

1. **一張卡一張圖。**（使用者：「前者」）
   ⚠ 這是**行為改變**，不是加功能：現在「勾四張寫四張」，之後「要四張圖就放
   四張卡」。好處是它跟這個 repo 的「一張卡一次處理，寫出去的正好等於接進來
   的」對得起來，而且畫布上看得到有幾張圖；代價是出貨的 recipe 要改，而**舊
   recipe 的 `charts` 那一格要有一道遷移**（一張卡勾了四張 → 拆成四張卡，
   或退而求其次：那一格留著，一張卡照舊寫多張，只有新加的 spec 走新路）。
   **這一條在第四刀之前不必決定**，先記著。
2. **要，而且它幾乎免費。**（使用者問「這是什麼東西」，解釋後採用）
   每一格框現在只知道自己 `y=270`，**不知道自己在第 3 列**。多算兩欄
   `row` / `col`，那個分群 `cell_edges` 已經在做了（熱圖排格子用的同一支）。
   有了它，「一列一條線」就不是一種新圖，只是 `Colour = row`。
3. **兩種色階都留，預設單色。**（使用者：「兩種都可 預設單色」）
   單一色相、由淺到深是通用規則；彩虹是 wafer map 的慣例，留成選項。
   殘差那種有正負的圖**必須**用發散色階（兩色相＋中性灰中點）。
4. **區域色重新取步。**（使用者：「好」）
   八個裡有四個落在亮度帶之外（2026-09-07 用配色檢查器量的），投影機上細線
   會發虛。⚠ 這一項**自己一刀**，不要混進別的：它會動到每一張圖的顏色，
   而「哪一張變了、為什麼」要看得出來。

## 11. 第二刀做完之後（2026-09-07）

`chart_spec`（角色配置）＋ `chart_draw`（`point` mark）＋ Scatter 那一張圖 ＋
`ui/graph_builder.py` 那個編輯器。**做的時候多付了四筆帳，都值得記下來。**

### 11.1 預設**不勾**散佈圖 —— 新增了 `DEFAULT_CHARTS`

`Which charts` 那一格的預設本來是 `",".join(CHARTS)`，於是把 `scatter` 加進
`CHARTS` 的那一刻，**一張全新的卡片預設就會寫一個畫不出來的檔案**，而畫布上
還掛著一條「你還沒挑 x 和 y」的黃字。三支測試同時紅 —— 那正是它們存在的理由。

前四張不必問任何問題就畫得出來，這一張要問兩個。**「可以畫」與「預設要畫」
是兩件事**，而這個 repo 以前沒有需要分它們的場合。

### 11.2 `ramp` 那一格之前**沒有家**

單色階／彩虹那個開關是這一刀順手加的（顏色代表數字的兩張圖共用），而它
只加進了 `chart_style.DEFAULTS`，沒有加進設定編輯器 ——
`test_every_setting_has_a_home_on_the_page` 當場抓到。

麻煩的是它的值是**字串**（`""` / `"rainbow"`），而那一排膠囊只認得 bool。
解法是 `chart_settings.CHIP_VALUES`：`鍵 -> (關的值, 開的值)`，沒列的就是
`(False, True)`。**刻意不給它自己一張表** —— 那一格的長相、說明、圖示與其他
七格一字不差，差別只有「開關對應到哪兩個值」，所以差別就只寫那一行。

### 11.3 類別軸不能借 `_xlabels`

`_xlabels` 把刻度當數字格式化（`_fmt`），而一個區域名餵進去是一句看不懂的
`TypeError: must be real number, not str`。**兩條軸都要問 scale 自己的
`label()`** —— 那正是 band 軸存在的意義，而第一版只在 Y 軸上守了它。

### 11.4 樣本資料要**兩個統計量**

設定編輯器的預覽用的是內建樣本，而它本來只有一個統計量 —— 散佈圖拿同一欄畫
兩次得到的是一條 45° 直線，那張預覽看起來像壞了。順手也發現：樣本上的散佈圖
需要一份 `SAMPLE_SPEC`，否則那張分頁永遠停在「pick x and y」，於是每一格設定
在那張圖上**看起來都沒有反應**（`test_every_editor_moves_the_preview` 抓到）。

### 11.5 還沒做

* **`(pick one)` 而不是拿第一欄當預設** —— 這一版做對了（第一版沒有，症狀是
  一張沒有人設定過的圖看起來像設定好了，畫出來是一團疊在同一點的圓）。
* 兩條軸都是數字的時候，**鎖定範圍只套在 Y 上**（同一組範圍套到兩條意思不同
  的軸會把圖擠成一條線）。X 的鎖定要等到有人真的要並排比兩批的橫軸。
* `line` / `bar` / `box` / `cell` mark 是第三、四刀。

## 12. 第一刀 b 做完之後（2026-09-07）

**結論跟計畫書寫的不一樣：不是「重新取步」，是「多取一階」。**

§9-4 假設有一組顏色可以同時服務兩件事。量完之後不成立：

| | 畫在哪 | 要什麼 | 舊那一組（`theme.REGION_COLORS`）|
|---|---|---|---|
| 區域框、模板編輯器、GLV 面板 | **深色的 SEM 影像** | 夠**亮**才看得見（那一份自己的說明就這麼寫） | 對 `#202020` 對比度全部 ≥ 3:1 ✅ |
| 四張圖 ＋ 散佈圖 | **白紙** | 夠**深**才讀得到 | 對白底**八個全部 < 3:1** ❌，四個落在亮度帶外 |

往下取步救得了紙、毀掉影像上的框。所以做法改成跟**深色模式**一模一樣：
**同一條色階、不同的一階，各自對著自己的底驗過** —— 不是把一組顏色翻過來。

* `ui.theme.REGION_COLORS` —— **一個字都沒動**（影像上的那一階）。
* `export.uniformity_charts.REGION_COLOURS` —— 白紙上的那一階（OKLCH L≈0.62，
  色相位移 ≤ 0.5°）。配色檢查器五項全過（最差相鄰 CVD ΔE 9.6 protan、
  正常視覺 16.9、對比度全部 ≥ 3:1）。

**身分靠色相與順序，不靠亮度** —— 第 3 個在哪裡都是那個藍。守著它的測試也
從「逐字相等」換成「同色相、同順序、紙上那一階比較深」，再加一條把
「投影機上看得清楚」寫成數字的（對白底 ≥ 3:1）。

### 12.1 順手量過但**沒有動**的兩處

* `decide_tree.LEAF_PALETTE`（`Write report` 的盒鬚圖用的）—— 對白底
  3.19 ～ 4.75，本來就是為紙取的，不必動。
* GLV 面板上那排區域色塊走的是 `theme.REGION_COLORS`（亮的那一階），而那個
  面板底是淺的。它有直接標籤，所以讀得出來 —— 但它跟這裡是同一個問題，
  **哪天要動 UI 的顏色時記得它**。

### 12.2 看圖時發現、這一刀**沒有修**的一件

盒鬚圖的標題是**靠左＋粗體**，另外四張是**置中**（`export/boxplot.py` 與
`uniformity_charts` 兩條路）。五張圖會落在同一頁上，所以那是「同一份報表裡
兩種長相」。不在這一刀的範圍裡（這一刀只動顏色），記在這裡。

## 13. 第三刀做完之後（2026-09-07）

`line` / `bar` 兩種記號、記號那一排膠囊，以及**一次趁還免費的改名**。

### 13.1 `scatter` → `chart`（使用者 2026-09-07 定調「現在改成一個中性的名字」）

加了折線與長條之後，`Scatter` 那個名字就開始說謊 —— 同一格畫得出折線圖，
檔名卻寫著 `-scatter.svg`。而**那個鍵當下還沒有人付過錢**：零份 recipe、
零份 fixture 在用它（只有 5 處程式碼 ＋ 2 個測試檔），因為它只活在一條還沒
合併的分支上。所以就在那個當下改掉：

* 鍵 `scatter` → `chart`，畫面上叫 **`Your own chart`**，檔名 `<defect>-chart.svg`；
* 卡片那一格從 `Scatter: what goes where` 改成 `Your own chart: what goes where`。

⚠ CLAUDE.md 那段 `bundle` 講的正是反面：名字含糊而改名要付一道遷移，於是
拖著，最後**混淆的是人**。這一次的差別只在時機。

### 13.2 render 出來才看到的三個 bug

計畫書寫的驗收是「一列一條線、排序長條」。全部測試綠了之後把圖畫出來看
（dataviz 的第 7 步：**驗證器只管顏色，版面要用眼睛看**），三個都在那一眼裡：

1. **`0` 被當成「沒有值」。** `_colours` 裡寫的是 `row.get(column) or ""`，
   而 `row` / `col` 的第一格就是 **0** —— 於是第 0 列拿不到自己的顏色（畫出來
   是灰的），而**圖例上它有顏色**。三張圖裡有一條是灰的，測試全綠。
2. **長條疊在一起畫。** 第一版只照顏色分群並排，於是同一群裡落在同一個槽的
   三格框畫在同一個位置 —— 看起來剛好像一張**堆疊長條圖**，而那正是這張圖
   說明裡寫著不做的東西。現在是「一個槽裡有幾格框就並排幾根」，寬度用整張圖
   最擠的那個槽算（每一根一樣寬，不然寬度會讀成一種意思）。
3. **數值軸當槽用時，18 個刻度標籤疊成一條黑線**，而且印成
   `114.81174999999998`。現在超過 12 個槽就跳著標，數字走 `_fmt`。

第 1 個是這三個裡最貴的：它**畫得出來、有顏色、而且是錯的**，是這個 repo
第八個那種 bug。

### 13.3 「用不到的角色」規則住在 `format_spec`，不住在編輯器

一份折線圖的 spec 帶著一個 `size` 的話，換回散點時它會**突然生效**，而使用者
不記得設過。第一版把這條規則寫在 `SpecEditor.spec()` 裡 —— 但編輯器只是其中
一個呼叫端，手寫的 recipe 走的是 `validate_params`（它叫的正是 `format_spec`）。
所以規則搬進 `format_spec`，而編輯器那一側照樣把每一格留著：**收起來不等於
清掉**，換回散點時原本挑的「大小」還在畫面上。

### 13.4 還沒做

* 四張老圖還沒改走 `chart_draw`（第四刀），所以現在有**兩套繪圖程式碼**。
* 角色插槽的 UI（第五刀）還是一個對話框，不是畫布上的插槽。
* 卡片改名 `Write charts`（第六刀）。

## 14. 第四刀做完之後（2026-09-07）：**後半量過之後不做**

`box` / `cell` 兩種記號做了 —— 到這裡「自己配的那一張」的記號字彙就跟四張
預設一樣齊：散點、折線、長條、盒鬚、格子。使用者現在可以拿**自己挑的兩欄**
畫出盒鬚圖或熱圖（例如 `col` × `region` 的格子，那是四張預設裡沒有的）。

### 14.1 為什麼「四張舊圖改走 `chart_draw`」**不做**

§7 給這一刀的價值是「少一份繪圖程式碼」，驗收是「四張的 SVG 逐位元組不變」。
量完之後這兩件事是**互斥的**：

* **序列化本來就是兩套。** 把 Box plot 那張跟 `mark=box` 畫的同一份資料
  拆成 token 比對，相似度 **0.01**。`export/boxplot.py` 用雙引號、屬性順序
  不同、每個元素換行、有 `class="boxplot"`、標題靠左粗體、沒有圖區外框；
  `uniformity_charts` 用單引號、不換行、標題置中。要逐位元組不變，就得把
  `boxplot.py` 的序列化**原封搬進** `chart_draw` 再加一個開關 —— 那不是少
  一份程式碼，是同一份加一個 if。
* **四張圖各自「先算再畫」。** 直方圖要分箱、profile 要逐欄取平均＋最小平方
  線、熱圖要鋪磚（兩種鋪法）。那幾段不是「記號」，是**資料轉換**，而
  `chart_draw` 吃的是一張已經攤平的長表。
* **版面常數也是四份**（`pad_l` 62/58、`pad_b` 56/46、圖例格式 `(n=9)`）。

**真正共用的那一半早就共用了**：`_head` / `_frame` / `_xlabels` / `_ylabels`
/ `_nice_ticks` / `_span` / `_axis_names` / `_text_attrs` / `fill_attrs` /
`_is_dark` —— `chart_draw` 一開始就是 import 它們，不是抄一份。

所以這一刀的後半**取消**。四張預設繼續走自己那一支，而它們與 `chart_draw`
共用所有的家具。§7 表格上的 ✅ 換成 ◐。

### 14.2 由此掉出來的一件真的該修

兩套序列化的代價**看得見**：五張圖會落在同一頁上，而 Box plot 的標題是
**靠左＋粗體**，另外四張是**置中**（§12.2 記過的那一件）。那不是「兩套引擎」
的必然，是兩份寫死的樣式 —— 值得單獨一刀，而且跟 `chart_draw` 無關。

### 14.3 `_is_dark` 那條規則差點被抄成第二份

`_cells` 第一版自己寫了一條「`t > 0.55` 就印白字」。熱圖那邊早就有一條
（`_is_dark`，配 `#ffffff` / `#1f2430`、粗體、`cw >= 34 and chh >= 14`）——
**同一句話長出兩種意思的起點**。改成呼叫同一支。

順手量到的：那條規則在色階中段碰得到 **3.2:1**（單色階 t≈0.49）——
印在連續色階上的字本來就到不了 4.5:1。不另外救它：色條是那張圖的尺，
`boxes.csv` 是那份表，兩者都在。

### 14.4 還沒做（誠實記著）

`GLOBAL_APPLIES` 是**一張圖一列**，看不到「這一張現在畫成哪一種記號」。
於是把 `Your own chart` 配成散點的人，在設定裡仍然看得到 `Whiskers`
（它對散點沒有作用）。要修的話得再加一張 `記號 -> 讀哪幾格` 的表，而那張表
會跟 `chart_draw` 漂 —— 留到第五刀（角色插槽）跟編輯器一起收。
